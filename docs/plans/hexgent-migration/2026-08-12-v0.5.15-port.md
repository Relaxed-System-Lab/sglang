# HexAgenT v0.5.15 Port Session

## Scope

- Repository: `Relaxed-System-Lab/sglang`
- Branch: `hexgent-v0.5.15`
- Upstream base: SGLang `v0.5.15`, commit `f63458b5be`
- Preserved branch: `hexgent-v0.5.9-main`

The port keeps the Python planner as the scheduling control plane and the Rust
PD router as the admission and execution plane. It does not merge the v0.5.9
runtime into v0.5.15.

## Implemented Modules

1. `python/sglang/hexgent/`: workflow state, hardware/model roofline estimates,
   output-length fallback, projected-ratio scheduling, reservations, revision
   publication, and planner HTTP API.
2. Rust PD router: global admission queue, event-driven plan refresh, token-aware
   prefill credit, live snapshot cache, placement validation, dispatch-time
   bootstrap creation, native fallback, safe mutation delivery, and completion
   events.
3. Worker controls: request metadata propagation, queue/running snapshots,
   request timing, revision-guarded local priority updates, and conservative
   reassignment compatibility.
4. Replay/profiling tooling: fixed-length DAG replay, exclusive service profile
   construction, scheduling summaries, Mooncake/CUDA telemetry calibration, and
   RunPod setup scripts.

## v0.5.15 Assessment

v0.5.15 is more convenient for HexAgenT in three areas: local scheduling already
understands request priorities, bootstrap conflicts and failure cleanup are more
robust, and queue/control components are better structured. These changes reduce
the amount of worker-side patching and make stale-action handling safer.

The release does not provide transparent migration after execution begins. The
safe implementation boundary remains:

- requests in the router global queue can change prefill/decode placement on
  every planner revision;
- bootstrap is created only at actual dispatch;
- dispatched requests keep their worker pair, although compatible waiting
  requests may be reprioritized locally;
- requests are not migrated after prefill, KV transfer, or decode starts.

## Retained Evidence

The curated H100/A100 archives under `real_trace_profiles/` are intentionally
retained. They contain workload lengths and v0.5.9 experiment evidence. Their
input/output lengths can seed v0.5.15 replay, but their measured latency is not
automatically a valid v0.5.15 SLO denominator.
