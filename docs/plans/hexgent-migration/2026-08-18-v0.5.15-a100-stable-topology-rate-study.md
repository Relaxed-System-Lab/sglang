# SGLang v0.5.15 A100 稳定版拓扑与压力实验

## 1. 实验目的

本次实验为验证 `hexgent-v0.5.15` 的实现。目标是在 baseline 与 HexAgenT 使用相同 trace、拓扑、到达率和 SLO 的条件下，提高请求压力、planner coverage 和 GPU 利用率，观察 HexAgenT 是否能够改善 workflow 尾延迟。

## 2. 环境与方法

| 项目 | 配置 |
| --- | --- |
| SGLang 基线 | v0.5.15 |
| GPU | 6x NVIDIA A100-SXM4-80GB |
| 模型 | Meta-Llama-3.1-8B-Instruct BF16 |
| Worker TP | TP1 |
| P-D backend | Mooncake intra-node NVLink |
| Prefill `max_running_requests` | 32 |
| Decode `max_running_requests` | 128 |
| HexAgenT 排序 | projected ratio `high_first` |
| Pairwise local search | disabled |

Baseline 和 HexAgenT 对每个最终配置执行 matched A/B：使用相同的 workflow、DAG、input/output token 长度、arrival rate、exclusive profile 和 worker 拓扑。所有最终 run 均为零请求错误，并等待全部 workflow drain 后再统计结果。

SLO 使用同模型、同硬件、同 dtype、同 TP 和同 release 的独占 profile。ShareGPT 与 BFCL-v3 的 workflow SLO 为串行 call 独占 latency 之和；HotpotQA/LATS 的 workflow SLO 为已知 DAG 上的独占 critical-path latency。

## 3. 拓扑与压力搜索

搜索过程中使用“有 queueing pressure、非零 planner coverage、配置中的每张卡均有实质工作、零错误且能够 drain”作为基本条件。

- 由于prompt length较短，prefill压力很小，ShareGPT 的 `2P+4D` 在 24 和 48 workflow/s 下 prefill worker 仍未利用满，planner coverage 仍为零，最终改用 `1P+5D`。
- BFCL-v3 的长 prompt 能显著占用 prefill。`2P+2D` 在 0.5 workflow/s 下产生 20.7% planner coverage，使 baseline 与 HexAgenT 的尾部差异充分显现。
- HotpotQA 的 fan-out/barrier DAG 在低压时结果受运行次序噪声影响。最终在 `1P+2D`、0.3 workflow/s 下将 planner coverage 提高到 53.6%，并让三张配置 GPU 的 median utilization 均达到 100%。

## 4. 最终性能结果

### 4.1 Workflow SLO ratio

| Trace | Topology / rate | Metric | Baseline | HexAgenT | HexAgenT 相对变化 |
| --- | --- | --- | ---: | ---: | ---: |
| ShareGPT | 1P+5D / 48 workflow/s | Mean | 1.420x | 1.426x | +0.4% |
| ShareGPT | 1P+5D / 48 workflow/s | P95 | 1.659x | 1.670x | +0.6% |
| ShareGPT | 1P+5D / 48 workflow/s | P99 | 4.574x | **3.439x** | **-24.8%** |
| BFCL-v3 | 2P+2D / 0.5 workflow/s | Mean | 4.972x | **4.435x** | **-10.8%** |
| BFCL-v3 | 2P+2D / 0.5 workflow/s | P95 | 9.388x | **7.387x** | **-21.3%** |
| BFCL-v3 | 2P+2D / 0.5 workflow/s | P99 | 9.536x | **7.624x** | **-20.0%** |
| HotpotQA | 1P+2D / 0.3 workflow/s | Mean | 4.090x | **3.966x** | **-3.0%** |
| HotpotQA | 1P+2D / 0.3 workflow/s | P95 | 5.096x | **5.057x** | **-0.7%** |
| HotpotQA | 1P+2D / 0.3 workflow/s | P99 | **5.175x** | 5.682x | +9.8% |

- ShareGPT 的 P95 基本持平，但最差 workflow 的 ratio 从 4.574x 降至 3.439x，极端尾部改善明显。
- BFCL-v3 的 mean、P95、P99 和 max 均明显改善。
- HotpotQA 的 mean 和 P95 小幅改善，但 P99/max 恶化；当前策略不能稳定处理 fan-out barrier 的极端尾部。

GPU 数值为采样窗口内的平均 compute utilization。Decode 通常是 memory-bound，因此不能仅用 compute utilization 判断其实际饱和度；median=100% 的 run 同时说明设备在主要执行窗口内持续繁忙。

| --- | --- | ---: | --- | --- |
| ShareGPT | Baseline | - | 54.2% | 71.3%, 78.8%, 67.8%, 73.4%, 63.5% |
| ShareGPT | HexAgenT | 26.6% | 56.1% | 68.3%, 77.1%, 74.9%, 77.1%, 63.1% |
| BFCL-v3 | Baseline | - | 48.5%, 83.5% | 32.8%, 45.2% |
| BFCL-v3 | HexAgenT | 20.7% | 56.7%, 83.5% | 35.5%, 49.1% |

## 5. Planner 开销

| Trace | Planner mean | Planner P95 | Planner max |
| --- | ---: | ---: | ---: |
| ShareGPT | 0.99 ms | 4.47 ms | 7.15 ms |
| BFCL-v3 | 0.26 ms | 1.54 ms | 7.18 ms |
| HotpotQA | 1.37 ms | 6.17 ms | 263.47 ms |

典型 planner P95 小于 6.2 ms，不是 ShareGPT/BFCL 的主要瓶颈。HotpotQA 存在一次 263 ms 的 solver tail，但其主要问题仍是 fan-out workflow 的极端尾部排序与 placement，而不是平均 CPU 求解开销。

## 6. 结论与后续约束

1. 后续排序统一固定为 projected-ratio `high_first`。
2. 绝对 SLO ratio 随压力升高而恶化并不是拒绝实验的理由；判断依据是同压力、同 SLO 下 HexAgenT 与 baseline 的 matched comparison。
3. 仍需至少三次独立重复并报告置信区间，才能把 BFCL 和 ShareGPT extreme-tail 的单轮收益表述为稳定结论。
4. HotpotQA 下一步应针对 barrier critical path 的 P99/max 做算法诊断，不能只根据 P95 小幅改善宣称胜出。
5. 跨 worker 分支必须先证明 safe-pair/action/migration 的完整闭环，再进入性能比较。
